# 方案

START → agent → tools → agent，agent选择finish则END。LangGraph负责状态传递、条件路由和循环。业务工具由本地函数实现，不需要额外服务。

agent将问题、历史和全部工具观察交给模型，模型以JSON选择search、read或finish；reason仅为简短决策依据。search返回文档元信息和摘要；read按ID返回原文。模型可多次搜索、查证、追问或结束。冲突不能仅凭版本日期裁决。工具输入及输出记录于trace，后续动作在下一条记录中。

状态保存本次请求的原文读取集，结束时检查引用来自已读取文档、版本一致、quote为非空连续原文。该校验只保证引用真实性，不保证回答的语义蕴含，仍需模型实测及人工核验。

选择JSON动作协议便于兼容不同聊天服务；不依赖服务特定的tool calling。生产应用可增加结构化输出重试、鉴权和检索索引。当前检索采用中文关键词，数据量小、可解释，但召回率有限。

offline_policy是独立确定性测试替身，不冒充ReAct；live_policy才调用真实模型。默认10次决策，最多30次，单次请求有超时及一次重试，LangGraph另设递归保护。

## 本轮实现更新

增加src/knowledge.py，实现长文分片与精确偏移，read支持片段ID并兼容文档ID。引用校验仅允许一个已读片段内的连续原文，避免读取部分文档却引用未读部分。片段ID由文档ID和位置生成，修改内容时应更新版本日期。

模型提示明确要求冲突后追加适用范围/优先级/替代关系查证。没有硬编码业务决策，图仅负责动作执行和预算。无重复调用、无结果最多两次改写和失败最多一次重试为模型指令，最终硬上限仍为max_steps。

检索按主题关键词及正文二元词命中评分，全部命中返回，保证小语料下的冲突召回；大语料的上下文规模控制尚未实现。字符偏移为Python Unicode字符索引，不是字节或UTF-16偏移。

补充可靠性处理：live引用校验失败时，反馈校验原因并允许一次模型修正，仍计入决策预算；如果模型连续提出多个合法工具JSON，只执行第一个，其他提议丢弃，待观察后重新决策。混合工具与最终答案的多对象输出拒绝处理。格式修复最多一次，错误原始响应仅作为协议诊断保存，不包含API请求头或密钥。
