# 需求

用户是查询企业制度的员工。目标是给出可核验答案，避免无依据回答和冲突时擅自决断。

输入为问题、可选历史，知识为带ID及版本日期的合成文档。提供检索及原文读取工具。输出为 answer、citations、gaps、status、trace。

范围包括明确答案、文档冲突、资料外问题、改写问法、上下文追问、工具失败。验收关注原文是否支持答案，替换文档是否影响回答及动作。界面、部署、持久化、多Agent不在当前范围。

成功标准：正常问题有原文；冲突返回双方引用并请求确认；无依据明确缺口；失败或步数耗尽显式返回；模型运行应展示不同观察引发不同后续动作。离线测试不视为真实模型验收通过。
